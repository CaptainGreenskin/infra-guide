# 从系统主线，到概念关系与连续阅读

本轮落实用户提出的整体要求：各章连贯，让中文初学者能把知识放回领域脉络。三条主线共用解释标准，Agent保持独立。章节数、实验数和历史8小时计数不增加；本轮质量目标是关系明确、路径一致和正文少跳步。

## 整体、领域、概念与章节

既有三张主线系统图继续说明Cloud怎样完成请求、AI怎样组织模型计算、Agent怎样完成委托。在同一学习路线里增加领域关系入口，直接跳到原有领域正文中的关系区，不新建概览过渡页。

14组关系覆盖P0前置基础、Cloud九个实际领域、AI三个领域与Agent领域。节点对应原有95个领域知识点及5组前置基础，每条边说明依赖、控制、数据或结果关系，共87条。它们是教学关系，不把所有节点画成必须依次执行的步骤，也不冒充共同运行过的生产系统。

领域图谱位于知识正文之后、案例之前，默认折叠。读者可以查看全部关系，或聚焦一个概念，读到定义、直接关系、相关机制章与原知识正文。跨领域出口说明继续深入的用途，不把整段Cloud或GPU课程强加为Agent先修。无JavaScript的初始HTML保留所有定义、关系和普通链接。

每个领域附一组闭卷推演与参考思路。例如容量题区分追平输入和排空积压，模型题区分隐藏元素增长与注意力分数增长；答案说明假设和证据范围，不把自评或点击当作掌握。

75章均有对应概念位置，图谱可反向打开实际机制章。搜索保持现有170个条目，新增概念关系作为原知识点的检索片段；精确搜索“节点放置”可定位`/module/native/?concept=placement#concept-relations`，不重复制造一组概念页面。

## 连续阅读采用同一顺序

原来的章末导航按目录分组排序，与学习路线存在冲突：Cloud全景学完会跳回资源章而跳过必要前置，P0结束又回全景；训练综合实战会跳到Cloud实战；共享章节的侧栏也会混入其他方向。

章末导航、所在主线和综合实战现由学习路线共同确定：

- Cloud全景之后进入P0，再走计算、网络、数据与平台主干；P0结束进入计算资源。
- AI训练综合实战之后进入模型推理，保持在AI方向。
- Agent的Kairo验收之后进入本方向综合设计评审，保持Agent侧栏与顶栏；训练不是前提。

目录仍按领域组织。侧栏只呈现当前方向及它的综合实战，计数注明“章数 + 1实战”。必要概念、后续用途与连续阅读是三种不同关系，界面分别表达；图谱中的相关章节不暗示全部必读。
