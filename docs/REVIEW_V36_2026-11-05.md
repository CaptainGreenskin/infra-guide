# 第36轮：启动失败时提供明确恢复入口

公开验收第35轮时，正文和原始SVG可读，但页内增强未初始化。浏览器当时记录到后续脚本访问未初始化领域数据的异常；抽查三份公开脚本字节与当前构建一致，重载后正常。没有捕获首发请求的完整网络响应，因此不把具体网络或CDN原因写成定论。

修订解决明确可观察的缺口：当恢复监测已载入，而后续初始化没有完成时，原来没有提示。首个内容包现在注册启动监测，app完成正常route后才标记data-site-ready并发送就绪事件。DOMContentLoaded之后仍未就绪则提供“重新载入”“继续阅读”。完整静态正文保留，正常启动保持安静，就绪后清除提示；不自动反复刷新，也不向读者暴露堆栈。

恢复监测与其他内容同包，132个规范源仍为9个公开脚本请求。若最初包含监测的脚本本身无法加载，此监测也无法执行，仍依靠原始静态正文及浏览器自身重载；没有承诺覆盖一切脚本/网络故障。

新增本地只绑定127.0.0.1的一次性测试服务器。仅首个runtime-04请求返回HTTP503，其后按正常源文件提供服务。不是生产路由，也没有修改远端访问权限。

- 1280px桌面实际看到正文与恢复提示，点击重新载入后data-site-ready为真，原pathname/query/hash保留，页内图解正常打开。

- 正常公开第35轮也再次验证了图解页内打开、镜像新内容及四成员下载包逐字一致。临时SVG标签和两个故障服务器已清理，测试视口已复位。
