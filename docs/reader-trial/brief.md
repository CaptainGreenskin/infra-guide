# 首批中文读者试读

目的：找出读者实际卡在哪里，以及读后能否把一个概念用于新条件。首批邀请3–5位真实读者，总计至少让Cloud、AI、Agent各有一份有效记录；参与者选择自己不熟悉的方向。当前尚未邀请或采集结果。

每人约15分钟，不要求安装环境。开始前只记录匿名编号、自述基础、阅读方向和设备；无需姓名、公司、联系方式或IP。邀请可由维护者在个人公众号、博客或公开社区发出，本站不自动代发。

可用邀请文字：

> 我在维护一份面向中文初学者和面试准备者的基础设施指南，想请你花15分钟试读一个不熟悉的小主题。请保留卡住的原句，按自己的理解回答概念问题和一道迁移题；看不懂也是有用反馈。试读不要求安装软件，也不收集姓名或联系方式。

先选一个方向，按下列范围连续阅读。每个链接直接定位第1节；不用跳到章末概念回顾，也不要求读完整章或运行程序。

## Cloud

读[TCP与I/O，第1–3节](https://captaingreenskin.github.io/infra-guide/article/tcp-event-loop/#section-1)：套接字与字节流 → 字节序号 → 消息解帧。

**10分钟后合上正文，用自己的话回答：**

1. 连接、字节流和应用消息是什么关系？
2. 长度头应写正文的字符数还是编码后的字节数，为什么？

**15分钟迁移题：**4字节长度头写明正文长6字节，正文是abcdef。三次读到的块依次为“头前2字节”“头后2字节+abc”“def”。在哪次能交付消息？前两次保留什么？

## AI

读[算子与性能分析，第1–2节](https://captaingreenskin.github.io/infra-guide/article/operator-profiling/#section-1)：输入与输出约定 → 稳定softmax。

**10分钟后合上正文，用自己的话回答：**

1. 减去同一最大值为什么不改变softmax的比例？
2. 输出行和为1，为什么还不能认定计算正确？

**15分钟迁移题：**一行输入是[3,3,3]，程序输出[1,0,0]，行和为1。它通过了吗？预期每项是什么，应该怎样核对？

## Agent

读[检索与上下文，第1–2节](https://captaingreenskin.github.io/infra-guide/article/agent-retrieval/#section-1)：检索到最终主张 → 片段与来源版本。

**10分钟后合上正文，用自己的话回答：**

1. 索引、来源正文与最终上下文是什么关系？
2. 同一文档的旧版与当前版为什么不能直接互换？

**15分钟迁移题：**检索第一名是旧调整99，真正送入上下文的只有当前调整27。能交付“本月总额27”吗？还缺哪份材料，需要核对哪些身份与条件？

## 怎样记录

这里的15分钟是观察期限，不是承诺每位初学者都能读完。按实际到达的小节记录；遇到没有读到的题，用`not_reached`，不据此判为理解错误。每个问题只使用上述范围内已定义的对象与机制；CUDA、ET、完整词元预算和性能计时留到相应后续章节。

按实际用时记录：

1. **2分钟**：能否找到指定章节及阅读范围。请指出当前不认识的词；记录导航卡点与原句。
2. **10分钟**：合上正文，用自己的话回答该方向的两问。记录原话，暂不讲解或纠正。
3. **15分钟**：回答迁移题，说明判据和下一步。若时间不够，记录未完成到哪一句，不能直接按错误理解计分。

读者可以随时结束。观察者只作提示定位，不替读者回答。评分在结束后按[rubric.md](rubric.md)进行；保留“没读到”“术语不懂”“机制误解”“设备/导航问题”的区别。

如果同一原句或概念在两位真实读者处重复造成卡点，优先修订并安排复读。单人体验也保留，不把小样本换算成“覆盖大多数人”或“掌握率”。实验运行另约20–45分钟，不混进15分钟阅读时间。

原始记录写入[observations.csv](observations.csv)，汇总到[summary.json](summary.json)。没有实际会话就保持空表和0样本，比例留空；网页自测与作者审读不填进读者表。

观察者在`reviewer_note`中同时记录试读开始时间、实际阅读链接和公开提交版本，避免把后续改版内容与本次卡点混在一起。
