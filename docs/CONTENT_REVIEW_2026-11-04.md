# 内容深改与交叉审阅记录

本轮目标是把实际领域入口写成可以直接学习的正文，优先打通计算、网络、Kubernetes 的机制链；同时审阅其余六个 Cloud 入口与 AI、Agent 代表章。没有把新增知识点计为独立长篇，也没有据此宣称覆盖大部分大厂面试。

## 从参考站学到什么

逐节查看了 AIInfraGuide 的 [3.1：为什么必须懂 Transformer](https://caomaolufei.github.io/AIInfraGuide/prerequisites/模块一-前置知识/transformer/31-ai-infra工程师为什么必须懂transformer/) 及相邻 Transformer 结构章节。值得借鉴的是解释顺序：先交代读者为何需要这个机制，再把组件、优化对象和数据路径对应起来，随后用张量形状、数字与代码走完一遍。图承担解释任务，而不只是装饰。

本站原先的实际领域入口只有定义和边界摘要；读者还要自己从后面的文章里拼回完整推导。这是内容组织的问题，增加目录和标签无法补足。本轮直接在每个知识点之后加入连续解释，保留「知识 → 原始资料 → 详解与案例」的阅读顺序。新增图、正文与算例均为原创，没有复制参考站图文；也不直接沿用其概括性技术表述。

## AI 与 Agent 代表章的实质核查

- Transformer 骨架：核对输入/目标右移、`[B,T,D]` 语义、参数与激活、逻辑分数矩阵与真实内核、Decoder-only 假设。发现基础课重排后，正文仍把 Attention 写成 0.2、Decoder 写成 0.3；已改为 0.3/0.4。移除「贯穿四章」的过时说法，将跨过中间章节的「下一篇」改为明确的深入链接。
- 位置编码：原文把采用可学习位置表的小 decoder 指向 0.4，实际代码位于 0.6；已修正。没有把给定 Q/K 的旋转内积恒等式推成整模型平移不变。
- Agent 运行时：核对任务、步骤、动作、尝试、回执与真实产物的区分；schema 不替代授权，超时不等于未提交。独立数据库恢复实验只支持其单 worker 和原子去重条件，不推广成任意工具的 exactly-once。Kairo 仍按接口映射与目标环境验收描述，没有虚构已接入能力。

## 图与交互的验证边界

新增 15 幅 SVG：责任矩阵、虚拟化分层、CPU 时间线、NAT 去回路径、TCP 序列、时延瀑布、调谐视图、发布快照、资源放置、恢复账本、预算窗口、排队曲线、版本兼容、授权约束、事件提交间隙。每幅有标题、说明与文字标签，不能只凭颜色判断。均核对画布内文本边界与文本交叠；代表图另做视觉检查。

两个可交互推导是数学教学模型：

1. CPU：P=100ms、Q=50 CPU·ms，两个线程在两个可用逻辑 CPU 上理想地运行 25ms 消费预算；一个线程为 50ms。明确省略 burst、祖先限额、竞争和调度细节，不将等待窗口当作内核实测保证。
2. 时延：新连接累计 20/50/90/210/250ms；复用既有且已解析的同源连接后为 0/0/0/120/160ms。120ms 包括发送、往返、排队与处理，不等于服务器 CPU 时间；与旧实验数据独立。

其他数字同样标注范围：TCP 的 SYN 消耗序号、丢段后累计确认停在缺口；发布的 surge 向上取整、unavailable 向下取整，终止对象可额外占资源；恢复账本编号不是 LSN 或 RPO 秒数；M/M/1 是均值解析模型，不是 p99 压测；授权交集不是完整云厂商策略求值器；inbox 不自动覆盖远端 API。

原始资料按机制放在相应正文的「原始资料」，包括 [Linux cgroup v2](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)、[TCP RFC 9293](https://www.rfc-editor.org/rfc/rfc9293)、[curl 计时定义](https://curl.se/docs/manpage.html)、[Kubernetes API 概念](https://kubernetes.io/docs/reference/using-api/api-concepts/)、[Deployment](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/)。资料与视频页保留 29 项既有推荐，本轮没有虚构新的视频观看记录。
