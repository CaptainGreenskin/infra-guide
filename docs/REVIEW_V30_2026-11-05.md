# 第30轮：让读者更快找到正文，减少首次加载请求

本轮不增加章节数，也不把界面修订计入21篇实质内容补强。全站正文审读仍为66/66章与95/95点；剩余8小时窗口继续按薄弱处和真实使用问题推进。

## 搜索实际内容，而不是重复的领域文本

旧搜索把章节关联的整片领域知识拼进每一章。同一个词会命中多篇并未直接讲它的文章，且无法直接进入独立知识点。新索引只有161个实际条目：66章和95知识点。章节按自己的小节索引，知识点链接自己的稳定锚点。

排序依次考虑标题、简介/主题、小节标题、正文、源码，最后才是分布在本页的多个词。输入空格分开的多个词时要求同时出现。`cpu.max`、`no_sync`保留标识符；`TP`不能只因`HTTP`里的字母碰巧连续就命中。大小写、全角与中英文相接的空格统一处理。此版本是明确规则的词面检索，不声称有语义搜索或错别字纠正。

显示正文片段与高亮、匹配位置标签、总数及前24项提示。片段加入中英文间距，HTML字符先转义；不把原始查询插入HTML。空搜索给6个实际入口，纯标点与无结果单独处理。方向键选择、回车打开、Escape关闭、焦点归还、结果的ARIA状态一起核对。修复初次按向上键跳到倒数第二项的问题。

浏览器实际验证：`traceparent`首项为Agent观测第2节；`cpu.max`首项为进程资源第3节，键盘回车后落点164px；`KV Cache`首项为平台知识点`knowledge-sv-kv`，手机390宽落点154px。手机搜索框356宽、整页390宽，无结果、关闭归还搜索按钮焦点正常。本页目录切换到推理指标点也落在154px。原始正文源码不会因搜索显示的中英文间距而改变。

## 123个规范源文件，9个浏览器请求

保留原始顺序和规范文件，由构建脚本生成6段稳定内容脚本，再加载阅读工具、搜索与应用入口。前一版公开页有122个外部脚本，本版规范源含新搜索共123个；公开页只请求9个。既有脚本的经典全局语义保持，未添加eval或额外包装函数。

清单记录每段来源、顺序、字节和SHA。检查拒绝重复文件、潜在跨文件同名函数和会改变严格模式边界的内容；新段也经过JavaScript解析。100条路由在根路径及`/infra-guide/`下，分别用原始文件与实际合并脚本初始化，逐字比较最终标题、正文和知识点。100份静态全文、脚本指纹和顺序另行检查。

按各请求分别gzip的离线估算，最后打包结果从1,001,426降至914,083字节。这是压缩字节估算，不是浏览器网络耗时、真实带宽或首屏速度的测量。规范源仍保留在仓库，压缩包会有重复文件；后续维护以规范源为准，生成脚本不可手工改。

合并脚本后的手机实测还覆盖：SLO好事件从989改990后得到99%、预算0、消耗率1倍；训练综合章展开7545字符源码，代码区域自己横向滚动，整页仍390宽；训练恢复图在弹窗中真实加载，未出现脚本错误。
