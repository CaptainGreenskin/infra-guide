# 从机制读到实现：三章正文与分层目录

## 这轮要解决的问题

读者知道概念名称，还需要看清它如何改变实际对象。以一次请求、一份缓存和一项任务为线索，正文先说明对象及其关系，再追踪正常执行、状态变化和失败结果，最后读完整程序。保留75章的URL、大节标题、原有锚点和完整代码。

参考[Transformer架构快速入门篇](https://caomaolufei.github.io/AIInfraGuide/prerequisites/模块一-前置知识/transformer/transformer架构快速入门/)的教学组织：先交付完整结构，再逐步解释组成部件，用具体计算连接工程用途。本轮吸收这种解释方法，正文、程序与SVG独立编写。

## 三条连续知识链

|章节|系统知识怎样展开|实现里核对什么|
|---|---|---|
|C2.1 云网络与请求路径|L4/L7 → 前后两段连接 → HTTP名称与TLS身份 → 后端资格和连接池 → 排空 → 重试与未知写入结果|实际本机HTTP代理和两个后端；连接复用、排空中的旧请求、最多尝试次数、共享截止时间，以及重复写入的实际金额|
|A3.6 推理性能|逻辑位置 → 块表与物理存储 → 完整前缀身份 → 引用和写时复制 → 逐出与重算 → 请求的计算机会|真实CPU块池存储两层注意力的K/V；独立全前缀重算验证数值，错误共享写必须失败；同一到达负载比较等待如何转移|
|G7 持久工作流|固定流程与动态计划 → 计划和事实分开保存 → 输入改变后的重规划 → 等待和审批信号 → 恢复后独立验收|每条推进命令新建进程，从SQLite恢复；补录数据加入后复用有效事实，拒绝旧审批；错误缓存可以令流程完成，但独立报告验收应拒绝|

三份程序都是各自范围内真实执行的教学实现。HTTP代理没有实施TLS终止；CPU注意力不等于GPU推理引擎；本地事务和脚本提议不等于远端工作流框架、LLM或Kairo接入。每章在相关机制和实验处说明条件，不把不同模型的输出合并成一份生产性能报告。

## 长章节怎样读

桌面目录、手机阅读目录和无脚本折叠目录共用正文的h3/h4小节。代码、图内标题和折叠选读不挤进主目录；原有作者ID保留。新增的文字标题生成稳定定位，已发布的小节目标另存快照，后续改标题时须保留原ID。岗位路线参数随目录跳转保留。

检查覆盖全部75章的代码与原锚点保留、小节目标、插入标题后已有目标稳定，以及岗位参数。图示和交互另做桌面、小屏实际阅读检查。程序有独立结果验收和失败对照，完整源码、执行记录与ZIP逐字绑定。
